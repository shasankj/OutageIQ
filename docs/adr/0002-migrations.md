# 0002: Schema migrations

Status: accepted (Phase 0)

## Context
The database is on a shared RDS instance. The owner runs every script personally; the assistant never connects to it. The schema is hand-designed and doubles as documentation raw material.

## Options
| Approach | Pros | Cons |
|---|---|---|
| Numbered plain SQL files + small Python runner | Every statement is readable; no ORM magic | No autogenerated diffs or downgrades |
| Alembic | Python standard, downgrades | Needs SQLAlchemy; hides the SQL |
| Flyway / Liquibase | Industry standard | Java tooling (excluded from this project) |

## Decision
`db/migrations/NNNN_name.sql` applied in order by `scripts/migrate.py`, tracked in a `schema_migrations` table.

## Consequences
Forward-only; fixes ship as new migrations.
